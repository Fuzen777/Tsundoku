# Features

> [!abstract]
> What the app does today. The full v1 design is in [PROJECT](./PROJECT.md).

## Install and Updates

- **Per-user installer**: installs for your account only, in `%LocalAppData%\Tsundoku`, without administrator rights, with a Start menu shortcut. WebView2 is downloaded if it's missing (it comes with Windows 11).
- **Updates**: Tsundoku checks GitHub for a newer version at startup. When there is one, a banner under the add bar offers Install and Restart, which downloads it with its progress, installs it and restarts; Later hides it until the next start. Updates are signed, and an older version is never installed in place of a newer one.
- **What's New before updating**: the banner's What's New shows the new version's changes, as its CHANGELOG section says them, before you install it. A release that came without them shows Release Notes instead, which opens its page on GitHub.
- **What's New after an update**: the first start on a newer version shows a card under the add bar with every CHANGELOG section since the version that ran last, up to this one, built into the app so it needs no connection. It stays, start after start, until its × closes it. A new install shows nothing; an install from before What's New, which didn't keep the version it ran, shows just this version's changes.
- **Check for Updates**: in Settings → About, with "up to date" or the new version as the answer.
- **Your data stays**: the history, presets, settings and Tsundoku's copies of the tools live in `%LocalAppData%\io.github.fuzen777.tsundoku`, kept through updates and uninstalls unless you tick the uninstaller's **Delete the application data**.
- **Portable copy**: `Tsundoku.exe` with a `.portable.txt` file beside it keeps everything in a `data` folder there instead: settings, history, tools, logs, the window's place and the WebView's data. It doesn't check for updates yet (Settings → About says so), and Start with Windows lists it as "Tsundoku (Portable)", apart from an installed copy. Only one of the two runs at a time. `Scripts\Build-Portable.cmd` makes one from the repository.

## Window

- **Mica**: Windows 11's backdrop shows through the window. Windows 10 gets a plain background.
- **Light or dark**: the window follows Windows' light or dark mode, or the one picked in Settings → Appearance: its colors, title bar, Mica, scrollbars and menus all change at once. In dark mode the current view sits darker than the window around it, with cards and fields lighter again, in plain grays.
- **Accent color**: Settings → Appearance → Accent Color picks the color of main buttons, selections, progress bars, links and the sidebar's counts: Indigo (to start with), Teal, Green, Amber, Rose or Purple, each with a shade for light mode and one for dark, or any color from the last swatch (Pick a Color), which opens Windows' color picker and keeps that color's hue with shades as readable as the others. It changes at once and is kept.
- **Icons for row actions**: the actions on each row or card (Start, Remove, Stop, Resume, Retry, Cancel, Open File, Show in Folder, Edit, Delete…) are icons, and resting the pointer on one (or reaching it with Tab) shows its name in a tooltip after half a second. A view's main actions (Add, Download, Start All, Clear Finished, Add Rule) keep their words.
- **Folders in your folder app**: Show in Folder and every Open Folder button open the folder in the app Windows opens folders with (File Explorer, or another file manager you set), with the file selected for Show in Folder. When that app is gone (a file manager uninstalled since), they open File Explorer instead, with no "Application not found" message. The window keeps responding while Windows opens anything: a folder, a file or a log.
- **No browser menu**: right-clicking the window opens nothing, apart from a text field (Cut, Copy, Paste) or selected text (Copy), so the WebView's Back, Reload, Save As and Print never show.
- **Remembered placement**: the window reopens at its last size and position, maximized if it was.
- **One window**: opening Tsundoku while it is already running brings the open window to the front.
- **Keep running in the tray**: with Settings → Running in the Background → Keep Running in the Tray on, closing the window leaves Tsundoku in the notification area, still downloading and watching the clipboard. Clicking its icon opens the window; its right-click menu has Open Tsundoku, Watch Clipboard (ticked while on), Start All Pending with how many links it would start, Pause All Downloads (Resume All Downloads while every download is stopped), and Quit Tsundoku, which asks first while downloads run. Off to start with: closing the window then quits, asking first while downloads run.
- **Progress on the taskbar**: Tsundoku's taskbar button fills with the progress of the downloads started since the queue was last idle, by size where every size is known, otherwise by how far each one is. It turns yellow while everything left is stopped and red once one failed, moves across while no size is known yet, and goes once every download has ended.
- **Tray tooltip**: hovering the tray icon sums up the same downloads, such as "3 downloading · 45% · 1 failed" (also waiting and stopped), leaving out what's zero, or reads Tsundoku with nothing going on.
- **Start with Windows**: Tsundoku opens when you sign in to Windows; with Keep Running in the Tray on, it starts in the tray without showing its window.
- **Notifications**: while the window isn't in front (hidden, minimized or behind another app), a Windows notification says when a copied link was added to Pending or started downloading (with its title), or waits there to be picked from (a channel, playlist or account, with its link), what the clipboard shortcut or the browser added, and how many links Start All Pending started from the tray. Clicking one opens Tsundoku. On to start with; Settings → Adding Links → Show Notifications turns them off.
- **Failed and finished downloads**: while the window isn't in front, a notification says when a download failed ("Couldn't Download" and its title; downloads that fail together are one notification, "Couldn't Download 3 Links"), and when every download started since the queue was last idle has ended ("All 12 downloads finished", or "11 of 12 downloads finished · 1 failed"). When none finished, the failures have said it already. Cancelled downloads don't count. A download that waits for you to open a site's check says so too ("A Download Needs You"), under Notify When a Download Fails. Each has its own switch in Settings → Adding Links, Notify When a Download Fails and Notify When Downloads Finish, on to start with.

## Navigation

- **Sidebar**: Queue, Pending, Watched, History, Presets and Rules at the top, Settings at the bottom. While Settings is open, it slides up under Rules with its sections listed below it. The sidebar scrolls when the window is too short for it.
- **Keyboard shortcuts**, listed in Settings → Keyboard Shortcuts and shown in each control's hover text ("Queue (Ctrl+1)"):
  - **Ctrl+V** anywhere in the window but a text field adds the links you copied, as if pasted in the add bar and added: one link shows its preview, several go to Pending.
  - **Ctrl+L** goes to the add bar, with its text selected.
  - **Ctrl+1 to Ctrl+7** open Queue, Pending, Watched, History, Presets, Rules and Settings, in the sidebar's order. Digits go by the key's place, so they work on an AZERTY keyboard too.
  - **Delete** in Pending removes the ticked links, as Remove Selected does, unless you're typing in a field.
  - None of them is one of the Clipboard Shortcut's choices, which work from any app.
- **About**: Settings shows the app's version, and "Portable" for a portable copy.
- **Data folder**: Settings → About shows the data folder's path, with Open Folder to open it.
- **Back up and restore**: Settings → About's Back Up… saves the settings, presets, folder rules and history, with what was downloaded before so the duplicate warnings keep working, in one zip file named with the day's date ("Tsundoku Backup 2026-11-06.zip"). Restore… loads one on another PC or after a reinstall: after you confirm, it saves the current ones as an automatic backup in the data folder's `backups` folder, so a wrong restore can be undone by restoring that, replaces them with the backup's and restarts Tsundoku. The tools, their caches, the logs, the queue and Pending are never in a backup, and a restore keeps which tools this PC uses and whether Tsundoku starts with Windows; finished downloads leave the queue. A backup from a newer Tsundoku is refused, and a portable copy's download folder beside it goes back to the default in an installed copy. Folders that don't exist on this PC are kept: a download to one fails with "Couldn't create the download folder" until it's changed.

## Adding a Video or Post

- **Add bar**: paste a link and press Enter or Add. A link without `https://` ("youtu.be/…") works too.
- **Ctrl+V anywhere**: with nothing typed into, Ctrl+V adds what you copied straight away, as if pasted in the add bar and added.
- **Several links at once**: pasting text with several links in it (one per line, or a paragraph holding them) sends them all to Pending instead of the preview card. Words that aren't links are left out, and each link is taken once.
- **Drop a link**: dropping a link anywhere on the window, such as one dragged from a browser's address bar, puts it in the add bar and fetches it right away. Dropping several links sends them to Pending.
- **Drop a file of links**: dropping a text file, a browser's bookmarks export (.html, as Firefox, Zen and Chrome export them) or an Internet shortcut (.url) anywhere on the window sends the http and https links in it to Pending, each once. Several files at once work too. A file with more than 300 links asks first, with about how long checking them takes. A file with no links says so ("No links found in bookmarks.html."), and so does a file of another kind. Files up to 10 MB are read.
- **Preview card**: under the add bar, the video's thumbnail, title, uploader, site, length, upload date and best quality ("1080p", or Audio Only). A spinner shows while yt-dlp fetches it, with Cancel; a new link replaces the one being fetched.
- **Already downloaded**: when the history has the video, the card says when and with which preset, shows the file's path with Open File and Show in Folder, and Download becomes Download Again. If the file was moved or deleted, it says so. The check uses the site and the video's ID, so every link to a video is caught: `youtu.be`, Shorts, a timestamp, a playlist it's in.
- **Refused links**: live streams, premieres that haven't started and pages of several posts that can't be listed (a Bluesky profile, say) each get a plain message. So do unsupported sites, unavailable videos, videos needing a sign-in or an age check, and network errors, with yt-dlp's own error underneath.
- **A site that asked to slow down**: while a site waits after answering that it's getting too many requests (see Queue), a link to it isn't read: the card says so, and from when to try again.
- **Videos with a password**: a video that needs a password (Vimeo's, and the other sites yt-dlp opens with one) shows "This link needs a password." with a password field and Unlock on the preview card instead of an error; Enter works too. A wrong password keeps the field and says it didn't open the link. Once it opens, the card is the usual one, and its download keeps the password: so does the history, so Retry and Download Again never ask twice. The password is never written in a log, Copy Details or a notification. Links on file hosts that need a password still say Tsundoku can't enter passwords for that site yet.
- **Image posts**: an Instagram, X, Bluesky, Pixiv or other image post shows its caption, author, date and what it holds ("2 images, 4 videos"). Each link is read by whichever tool suits it, yt-dlp or gallery-dl, and by the other when the first can't, so the user never has to choose.
- **Files on Pixeldrain, Gofile, Bunkr and Cyberdrop**: these download through the image tool whatever they hold. A file that's neither an image nor a video (a .zip, a .pdf) shows as "1 file", titled with its name, with no picture. A folder or list of several files, some of them neither images nor videos, shows them as a list of their names and sizes (as a shared folder's, flat and numbered) rather than a strip of blank tiles, to tick the ones wanted the same way.
- **Download a post**: a post has Download without a preset, since its files are kept as the site gives them, each named as Settings → Posts of Images says ({numberIfMany} is the number only when several of a post's files are downloaded): "natgeo 2026-11-04 DfPQchkG1tg 1.jpg" (the account, the post's date, its ID and the file's place in it) to start with. They all go into the site's folder (Instagram, X, or the site's name) in the download folder, by the first rule, which can be changed. Files already there are skipped, so Download Again only fetches what's missing.
- **Pick a post's files**: a post of several files shows them on the preview card as small pictures, a play mark on each video and its number in the post, all ticked: untick the ones you don't want, or untick them all with the box above them and tick a few. Download is off while nothing is ticked. Only the files ticked are downloaded, and the queue says how many ("3 of 6 files"). The history remembers which files each download took, so when a post downloaded before left some out, its strip marks those Not Picked, with a ring, and the others Downloaded, says how many weren't picked last time, and ticks just those: Download Again gets the rest in one click; once the ticks change, it only says how many weren't picked. Posts downloaded before this was kept count as taken whole. The same List, Masonry and Gallery buttons and − and + as a channel's list change how the files show (as rows, in their own shapes or as squares, to start with) and how big, remembered apart from the channels' choice.
- **MEGA, MediaFire, Google Drive, Dropbox, OneDrive, pCloud, WeTransfer, the Internet Archive, Yandex Disk, Box, Icedrive, 1fichier, SwissTransfer, Files.fm, upload.ee, TransferNow, Filemail, Workupload and Buzzheavier**: a link to a file or a shared folder shows its name, date and what it holds (the file's size, or "14 files, 1.2 GB") and has Download without a preset. Tsundoku downloads these itself, nothing to set up. A shared folder keeps its own folder and subfolders inside the download folder; files already there are skipped. MEGA, MediaFire and OneDrive files are checked once they arrive, and a damaged one is deleted so Retry downloads it again. OneDrive takes its short links (1drv.ms, old and new), the onedrive.live.com links they lead to and its older redir, embed and download links, and needs no account; a deleted file, a link that's private or turned off, one that needs a password and a shared folder with folders inside it (which OneDrive doesn't let Tsundoku read yet) each say so. pCloud takes its public links from either of its data centres (u.pcloud.link and e.pcloud.link). A WeTransfer link (we.tl or wetransfer.com) gives the transfer's files; an expired or deleted transfer says so. An Internet Archive item (archive.org/details/…) is a folder of the files its uploader gave it, without the copies archive.org makes of them; a link to one of its files downloads that file. Its videos and audio go through yt-dlp, with a preset, as before. Yandex Disk takes its public links (disk.yandex.ru, yadi.sk); a single video there still goes through yt-dlp. Box takes its shared links, a company's included; Box Notes in a Box folder are left out. Icedrive takes its public links (icedrive.net/s/…). 1fichier takes its file links (1fichier.com/?…) as a free download, without an account: Tsundoku waits out 1fichier's countdown before each file (the row says Counting Down, with the time left), and when 1fichier makes free downloads wait between each other (up to a few hours), the download waits in the queue and says when it goes on. A file with a password and one its owner keeps for 1fichier's subscribers say so. A SwissTransfer link (swisstransfer.com/dl/… or the older /d/…) gives the transfer's files, in a folder named after it when there are several; an expired or deleted transfer, one with a password and one whose downloads are used up say so. Files.fm takes its folder and file links (files.fm/u/… and /f/…); a deleted one says so, and a folder with folders inside it says Tsundoku can't read those yet. upload.ee takes its file links (upload.ee/files/…); a deleted one says so. A TransferNow link (transfernow.net/dl/…) gives the transfer's files; an expired or deleted transfer and one with a password say so. A Filemail link (filemail.com/d/…) does the same, and its files are checked once they arrive. A Workupload link (workupload.com/file/…) or a Buzzheavier link (buzzheavier.com/…) shows its ID and "Size unknown" until its file is known, since both sites check for a person before they show anything: its download waits for you to open its check (see Queue), and once it's done, the row and the history name it after its file. The same goes for a link on any of these hosts whose own page asks for a check: it shows the end of its address as its name, "Size unknown", and waits for its check. A mirror page from MultiUp (multiup.io/download/…) or Mirrored.to (mirrored.to/files/…, or its short mir.cr links) opens to its first working mirror on one of these hosts, those that give a checksum and make no one wait first, else on a site Tsundoku reads images and files from (GoFile, Pixeldrain), then reads like that mirror's own link; a page whose mirrors are all on other sites names them. Google Docs, Sheets and Slides in a Drive folder are left out. A link missing its key, a password-protected link, a used-up download limit and a link on one of these hosts that isn't to a file or folder Tsundoku recognizes each get a plain message. When a host wants to check you're a person before a file, its download waits in the queue for you to open the check (see Queue). A MediaFire link copied from a page's Download button is downloaded from as it is while it works, and gives a download waiting for that file's check what it needs.
- **Short links**: a short link from Bitly (bit.ly), TinyURL, is.gd, X (t.co), Cuttly, RB.GY, Tiny.cc, T.LY, Google (goo.gl), Ow.ly or Buffer (buff.ly) opens to where it leads and reads as that link would: the card shows the video, post or file it leads to, and the download, the history and the folder rules go by that address. A short link to a MultiUp or Mirrored.to page opens to the mirror. Tsundoku only asks the short-link site where the link leads and never opens a page there: a short link that shows a page before leading anywhere (a preview or a warning) says so, so you can open it in your browser and add the link it ends on. A short link the site doesn't know says it isn't available, and one that leads to a site Tsundoku can't download from names that site; copied, it leaves Pending quietly, as that site's own link would.
- **Pick a shared folder's files**: a file host's link that holds several files (a shared folder, an Internet Archive item, a transfer of several files) lists them on the preview card as a folder tree, every file ticked, so Download still takes the whole folder. Each file shows its name and size, each folder its name and how many files it holds with their size; a folder's box ticks everything under it, its chevron folds it, and the box above the list ticks them all, with "12 of 340 Files · 1.2 GB". A folder of more than ten files has a filter (matching anywhere in a file's path, ignoring case): while it has text, only the files that match show, under their folders, and the box above ticks just those. A list of more than 200 files starts with its folders folded. Download is off while nothing is ticked. Only the files ticked are downloaded, into the folder's own structure, and the queue says how many ("2 of 340 files, 14.2 MB"). The history remembers which files each download took, so a folder downloaded before marks each file Downloaded or Not Downloaded, says how many weren't downloaded before, and ticks just those: files the owner added since count as not downloaded. Folders downloaded before this was kept count as taken whole. A picked file the folder no longer has is skipped; when none of them is left, the download fails saying so rather than taking the rest of the folder.
- **Without Deno**: a YouTube preview warns that some formats may be missing, with Set Up Deno, which downloads it and reads the link again.
- **Download**: pick a preset (the one a rule picks, else the default, is preselected) and Download: the video joins the queue, and the card and the add bar clear. With a video already downloaded, it's Download Again; with the same preset as before, it asks first, since the new file replaces the old one.
- **Where it goes**: beside Download, the folder the download will be saved in and what picked it: a rule ("Rule 2"), the preset's folder or the download folder. Clicking it opens the rules, the presets or Settings.
- **Another folder for this one**: the folder icon after it (Change Folder…) picks a folder for this download only, shown as "Picked for This One", whatever the rules say; the arrow beside it (Use the Usual Folder) goes back.
- **Preset picked by a rule**: when a rule picks the preset, "Rule 3" shows beside the preset picker, and clicking it opens the rules. Picking another preset takes it instead.
- **Already in the queue**: the card says so, without Download.

## Channels, Playlists and Accounts

- **Pick what to download**: a link to a YouTube channel (`/@name`, `/channel/…`, `/c/…` or `/user/…`, with any tab), a YouTube playlist, an Instagram account or an X account (`x.com/name` or `twitter.com/name`, or its Replies, Highlights or Media tab) lists what it holds in the preview card, without reading each video or post on its own: "Listing the channel's newest videos…" meanwhile ("This can take a minute" for an account, which is read slowly). Instagram and X accounts need a browser signed in to the site, as their posts do (Settings → Downloads' cookies). A link to one video in a playlist (`watch?v=…&list=…`) is still that one video.
- **What's listed**: a channel's newest 50 videos from its Videos tab (not its Shorts or past live streams), an Instagram account's newest 50 posts and reels, an X account's newest 50 posts with pictures or videos (as its Media tab shows them, so not its text-only posts or what it reposted; X keeps its posts with photos and those with videos as two lists, which are read side by side and merged by date, and posts of an animated GIF only are in neither), newest first, or a whole playlist in its own order. Each post is downloaded from its own page, as if its link had been pasted, so its files are named with the account's handle. A video the playlist holds twice is listed once, and premieres that haven't started and live streams are left out. Another site's playlist (a SoundCloud set, a Bandcamp album) is listed too when it gives each item a link of its own.
- **The card**: the channel's or account's picture (a playlist's first thumbnail), its name, the site, and what it is with how many are listed ("Account · Newest 50 of 8,634 posts"). Then the items, each with a box to tick it.
- **Load More, Load 50 New and Load All**: when only the newest were listed, Load More under the items lists the next ones (50 more videos or X posts, 48 more Instagram posts), Load 50 New lists on past everything downloaded or in the queue until 50 items that aren't are listed (or the list ends) and then scrolls to the first of them, and Load All lists everything, with how many there are when it's known ("Load All (8,634)"). Instagram says how many posts an account has; a YouTube channel's count is read a moment after the card opens, from the channel's own list of its videos (its Videos tab doesn't say); X doesn't say how many posts with pictures or videos an account has, so Load All has no number there and its hint says the site doesn't say. Load 50 New and Load All add the items as they're read and count them, with how many are new ("Listing… 150 of 8,634 posts · 12 new"); Stop keeps what's listed, and any of the buttons carries on from there. Ticks stay as they were, and new items that arrive are ticked as the first ones were, unless nothing was ticked when the load started. An account's posts stay newest first as more arrive. Instagram is read a page of 12 at a time (gallery-dl waits 6 to 12 seconds between pages, and Load All 10 more seconds after each 8 pages), so a big account takes a while, which a line under the count says; if it asks to slow down anyway, the card says when to try again and Load More waits until then, as downloads do. Closing the card or reading another link stops it. Once everything is listed, the card says "8,634 posts" instead of "Newest 50 of 8,634 posts".
- **Hide Downloaded**: a button before the view buttons hides the items downloaded before or already in the queue, so only the new ones show, with "· 10 hidden" after the count. Select All and Download Selected take only the items shown; a hidden item's tick comes back with it. "Everything listed so far is downloaded or in the queue." shows when nothing's left, and Load More still lists the older ones. It's remembered with the view.
- **Only one type**: when the items are of several types, a row of choices before Hide Downloaded shows them all or only one, with how many there are of each: All, Images (posts of pictures only), Videos (videos, and posts of videos only), Mixed (posts holding both) and Files (other files, such as archives), offering only the types there are. Images on an X account's list, say, shows only its posts of pictures, and Download Selected takes only those; the count says how many the type hides. Select All ticks or unticks only the items shown, so the others keep their ticks, and Videos Start As shows only while videos are shown. The choice lasts while the list is open.
- **List, Masonry or Gallery**: three buttons on the right of the select-all box show the items as a list (thumbnail, title, date, roughly as YouTube says it: "3 weeks ago", and length, or what a post holds), as a masonry of their pictures in their own shapes, or as a gallery of pictures all cut to one shape (16:9 for videos, square for posts). In the two views of pictures, − and + make the pictures smaller or larger, so more or fewer fit on a row. A picture shows a video's length, or how many files a post holds, in its corner, Downloaded or In Queue under it, and its title and details when hovered; an unticked one is dimmed. The view and size are remembered, and the new items of a watched source show the same way. Gallery to start with.
- **New ones ticked**: items not downloaded yet start ticked. One the history has is greyed, unticked and marked Downloaded (hovering says when and with which preset), and can be ticked to download it again; one in the queue is greyed and marked In Queue. The box at the top ticks every item or none, and counts the ticked ones.
- **Download Selected**: queues each ticked item as its own download, as if its link had been pasted, so rules, presets, Instagram's pauses, the history and `archive.txt` treat it as any other. Videos start with the preset a rule picks for them, else the one in Videos Start As (the default one to start with); posts need no preset. Downloading again with the preset used before asks first, since the new files replace the old ones. In the queue, they sit together under the channel's, playlist's or account's heading (see Queue).
- **In Pending**: a channel, playlist or account link, copied, pasted with others, sent or found in a dropped file, waits in Pending under Needs Attention, where nothing starts it; its Pick What to Download opens this list in the preview card, and once Download Selected queues what's ticked, or it's watched, it leaves Pending.

## Watched

- **Watch a channel, playlist or account**: the list a channel, playlist, Instagram account or X account opens in the preview card has Watch, which asks what counts as new now (nothing, only what's added from now on; its latest 30 or another number; or everything listed), Save In and Videos Start As, then keeps it in the Watched view, between Pending and History in the sidebar. What the history or the queue already has never counts as new.
- **One card per source**: its picture, name, kind and site, then "Checked 2 hours ago · 3 new · 12 downloaded · 2 skipped · Last post 3 weeks ago" (the new count in the accent while there are some). Check Now reads it again in the background, keeping to a site's slow-down wait: sources on different sites are checked side by side, one at a time per site; an account's check reads only what its site sends first (an Instagram account's newest page, unless eight or more posts came since; an X account's newest 19 or so posts with photos and 19 or so with videos, read side by side, unless 16 or more came since), so it takes a few seconds rather than half a minute or more on Instagram, and one page of posts rather than two or more on X; a check that fails says why on the card, with the fix the preview card would offer. Show Downloads in History opens the history at what was downloaded from it. Edit changes Save In and Videos Start As; the ⋯ menu has Stop Watching, which asks first.
- **Latest downloads on a folded card**: under the summary, a row of pictures of what was downloaded from it, the latest first, as many as fit (square for posts, wide for videos). Click one to open its file; one whose file is gone is dimmed. Hover for its title and the day it was downloaded.
- **Fold and unfold**: the chevron, the picture or the name folds a card to that summary or opens it on where its downloads go, its new items and Skipped Before. A card opens by itself while it has new items and folds once they're dealt with, unless you opened or closed it yourself; Expand All opens every card, unfolding the sites folded away too, and Collapse All folds every card. Tsundoku remembers what you opened while it runs.
- **Grouped by site**: the cards sit under a heading per site (instagram.com, x.com, youtube.com), with how many sources and new items it holds and Check All Under it; a heading folds its group away. Group By None lists them together. Sources whose last check failed sit above the rest under Needs Attention, whatever the grouping, until a check works.
- **Sorted**: by Most New (to start with), Name, Last Checked, Latest Post or Date Watched, either way round; what a source doesn't have (never checked, no dates) comes last. How it's grouped and sorted is remembered.
- **Check All**: on the title's right, checks every source: those on different sites side by side, those on one site one after the other in the order shown, so an X account doesn't wait for the Instagram accounts above it.
- **What's new**: a check keeps only what the source, the history and the queue don't know, reading a channel's or an account's newest items until it reaches three known ones in a row (so pinned posts don't stop it early), and a playlist whole. New items show on the card, ticked unless they were downloaded since; Download Selected queues the ticked ones and skips the rest, which never come back as new, and Skip All skips them all. When the new items are of several types, the same choice of type as in the preview card shows one type only; Download Selected then skips only the unticked items shown and Skip All only those shown, so the items another type hides stay new. The sidebar counts the new items.
- **All New Items**: beside Sources at the top, shows every source's new items in one list, the latest posted first, each with its source's name under it (and first in its details in List), with its site when another source has the same name ("NASA on x.com"). Download Selected queues the ticked ones, each with its own source's folder and preset, and skips the rest; Skip All skips every source's. Its choice of type works as on a source's card. An item two sources found shows once. Its count is on the button. Its list takes what the window's height leaves it and scrolls on its own, with Skip All and Download Selected always in sight; when the view is short (the What's New card above it), the list keeps about 10 rem and the view scrolls. When a check finds something (Check Now, Check All or Check All Under a site), Watched switches to All New Items by itself, from any view, and stays there until Sources is picked; a check that finds nothing, and the items a new source starts with, leave it as it was.
- **Skipped Before**: folded under the new items, in the same view as them (List, Masonry or Gallery), nothing ticked to start with; tick what you want after all and Download Selected queues it.
- **Save In** beats every rule, with the rules' placeholders ({site}, {uploader}…); a folder that isn't a full path goes inside the download folder. Empty, the rules decide. Videos Start As picks the preset; left as it is, a rule's preset, else the default, is used.
- Checks run when you press Check Now, for now: a schedule, notifications and Download Right Away per source come next.

## Pending

- **Links waiting to start**: the Pending tab holds links pasted or dropped several at once, or copied while Watch Clipboard is on, oldest first to start with, until they're started. They're kept through a restart.
- **Group and sort**: the toolbar's Group By has Status, a switch of its own that groups the links by where they stand (ready to start, downloaded before, not read yet, needs a password, couldn't be read, in the queue), and None, Site, Folder or Rule side by side: their site, the folder they'll be saved in, or what picks that folder (the rule's number with the part of its folder that doesn't change, so `Downloads\{site}` shows Downloads, then a preset's own folder, then the download folder). With both, each status's group holds the other groups under smaller headings. Each group has a heading with how many it holds; clicking it folds the group away, and Pending and the queue each remember their folded groups while Tsundoku runs. In Pending, a box on each heading ticks or unticks every link in the group, so Start Selected sends everything bound for one folder at once. Grouped by folder, a row shows only what picks its folder ("Rule 3"), since the heading shows the folder. It sorts them by date added, title, uploader or site, either way. Links whose folder or site isn't known yet come after the others, by where they stand, or without a heading under their status. Pending and the queue each keep their own choice through a restart.
- **Watch Clipboard**: off to start with, turned on in Settings → Adding Links or with the box on the Pending tab. While Tsundoku is open, even minimized, links copied in any app go to Pending: one link, or several on their own, separated by spaces or lines. A copy holding anything else (a sentence with a link in it) is left alone, and so are direct links to a file (an image, a PDF), what's copied inside Tsundoku itself, what a password manager marks private, and what was copied before the watcher was turned on.
- **Checking copied links**: a copied link is read before it shows, with "Checking 2 copied links…" meanwhile. One that no tool can download (a Google Doc, a shop, a news page without a video) leaves without a word, and so does one already downloaded or in the queue. A channel, playlist or account stays, under Needs Attention. One that needs a fix, such as signing in, shows with its message and fixes like any other. So does a MEGA, MediaFire, Google Drive or Dropbox link Tsundoku doesn't recognize, so a file you meant to download doesn't go missing.
- **Checking links from files**: links from a dropped file are checked the same way, with "Checking 1,234 links from files…" meanwhile: one with nothing to download (an ordinary page, a site no tool supports) leaves without a word, and a channel, playlist or account stays under Needs Attention. The rest stay as links pasted by hand do: one downloaded before shows marked and isn't started by Start All, and one that needs a fix says so.
- **Long lists**: thousands of links are added at once, the list updates a few times a second at most while they're read, and Pending shows 200 at a time, with Show More under them.
- **Clipboard Shortcut**: a key combination picked in Settings → Adding Links (Ctrl+Alt+D, Ctrl+Shift+D, Ctrl+Alt+V or Alt+Shift+D; none to start with) adds the links on the clipboard to Pending from any app, as if pasted there, so each shows even when nothing can download it. It works with Watch Clipboard off. A shortcut another app already uses is refused, keeping the one picked before.
- **Send from your browser**: Settings → Adding Links → Send from Your Browser explains how to add a bookmark to the browser's toolbar, with Copy Bookmark Address. Clicking the bookmark on a page sends that page to Pending, as if pasted, and the browser stays in front: Tsundoku starts if it isn't running (in the tray with Keep Running in the Tray on), and a notification says what was added. The browser asks once whether to open Tsundoku. Works in Firefox, Zen, Chrome, Edge and the rest.
- **Send buttons on Instagram, X and YouTube**: a userscript, copied from Settings → Adding Links with Copy Userscript into Tampermonkey or Violentmonkey, puts a Send to Tsundoku button (Tsundoku's icon) on each Instagram post and reel, after Share, on each X post, in its row of actions, and on YouTube's watch pages beside Share, on Shorts in their column of actions, and in the corner of every thumbnail in feeds, search results, channels and the list beside a video (shown on hover, and on the preview that plays over a thumbnail). One click sends that post or video the way the bookmark does, without opening it or copying anything. A sent one keeps a check for as long as the tab is open, and the buttons follow the sites as they scroll and move between pages, in their light and dark themes.
- **Click'n'Load buttons**: Settings → Adding Links → Take Links from Click'n'Load Buttons (off until turned on) lets a protected link folder on FileCrypt send its links to Pending with its Click'n'Load button, once you've passed its check in your browser, the way it sends them to JDownloader. Tsundoku listens on this PC only, takes links only from the sites it lists, and never runs a page's script. The links are read as links from a dropped file are: those nothing can download leave without a word, one downloaded before is marked, and none starts by itself, even with Download Right Away on. While they're read, Pending says "Checking 12 links pages sent…", and a notification says what came ("FileCrypt Sent 12 Links") while the window isn't in front. JDownloader uses the same port, so only one of them can listen at a time: when another app has it, the setting's line says so, with Try Again. In Chrome and Edge, and in Firefox and Zen, the browser may ask once per site whether the page may reach devices on your network: allow it for the button to work.
- **Download Right Away**: copied links, links the clipboard shortcut adds and pages sent from the browser start downloading once they're read, with the preset a rule picks or else the default one, instead of waiting to be started. A rule can turn it on or off for the links it matches, whatever Settings says. One downloaded before still waits, marked, and a channel, playlist or account waits under Needs Attention. Links pasted or dropped by hand still wait.
- **Pick a post's files**: Pick Files on a read post's row opens the same strip (or list) as the preview card, under its details; ticks show at once, even several in quick succession, and are kept with the link, through a restart, and Start downloads only those. A post downloaded before starts with only the files left out then ticked. The row says how many it takes ("2 of 6 files") while some are unticked, and Start is off while none is.
- **Pick a shared folder's files**: Pick Files on a read shared folder's row opens the same list as the preview card; the ticks are kept with the link as they change, through a restart, and Start downloads only those. A folder downloaded before starts with only the files it didn't take then ticked. The row says "12 of 340 files, 1.2 GB" while some are unticked, and Start is off while none is.
- **Read in the background**: each link is read one at a time, so its row fills in with the thumbnail, title, uploader, site and what it holds, as the preview card shows them. A paced site's links (Instagram, X, Pixiv, Tumblr) wait the same random pause between reads as between files (Settings → Pacing), and links from other sites are read meanwhile.
- **When a site asks to slow down**: a link whose site answered that it's getting too many requests goes back to waiting instead of failing, and the site's links aren't read until its wait ends, as in the queue, while other sites' links are. Each says so, with the time it continues and the time left.
- **Already downloaded**: a link the history has says when and with which preset, and its Start becomes Download Again. Two links to the same video are kept once. A link already in the queue says so.
- **Start All**: sends every link to the queue except those downloaded before, already in the queue, that couldn't be read, that need a password or that need picking (Needs Attention). Videos start with the preset a rule picks, else the one picked in Videos Start As (the default one to start with); a link's own preset picker overrides both. A link that follows Videos Start As shows Default in its picker (hovering it names the preset), and picking Default makes a link with its own preset follow it again. Links still being read start once they're read, unless they turn out to be downloaded already.
- **Select**: with links ticked (or all of them, with the box at the top), Start Selected and Remove Selected act on those instead. Starting a video again with the preset it was downloaded with asks first, since the new file replaces the old one.
- **Undo**: removing links (Remove Selected or a row's Remove) shows "Removed 12 links" at the bottom of the window for 8 seconds, with Undo, which puts them back as they were: in the same places, ticked if they were, with their presets and what was read. The message waits while the pointer is on it or it has the keyboard's focus, and Escape or its × closes it. Only the latest removal can be undone, and a link that's in Pending again by then (copied again, say) isn't added twice.
- **Each row**: Start (or Download Again), Remove, and the preset picker for a video, with "Rule 3" beside it when a rule picked the preset. A link that couldn't be read shows why, the same fixes as the preview card, and Try Again.
- **Links with a password**: a link that needs a password waits as Needs a Password, with the password field and Unlock on its row. It isn't failed and never leaves by itself, a copied one included, and Start All and Download Right Away leave it until a password opens it; one started before it was read starts once it's unlocked. A wrong password says so on the row. The password that opened it goes with it to the queue, and a link the history has a password for opens with it without asking.
- **Needs Attention**: a YouTube channel or playlist, an Instagram or X account, or another site's playlist, whichever way it came in, waits at the top of Pending under Needs Attention, above the other links however they're grouped (under Other Links while the list isn't grouped). It's never read in the background and nothing starts it: Start, Start All, Start Selected, Download Right Away and the tray's Start All Pending leave it, even one started before it was read. Its row says what it is ("This is a channel. Pick which of its videos to download."), and Pick What to Download opens its list in the preview card above, as pasting it would; once Download Selected queues what's ticked there, or Watch keeps it in Watched, it leaves Pending. A second link to a channel or account already there (its Shorts tab, say) is kept once. It stays through a restart, and Remove takes it out as any other.
- **Where it goes**: under a read link's details, the folder it will be saved in and what picked it (a rule, the preset's folder or the download folder), as the preview card shows it. It follows the preset the link would start with, and clicking it opens the rules, the presets or Settings. Change Folder… picks a folder for that link alone, kept through a restart and used when it starts.
- **Apply a rule to one link**: the rules button after Change Folder… (Apply a Rule…) lists every rule by its name or number, and the one picked decides that link's folder, preset and file name before any other rule, whatever its conditions, even one that's off ("(Off)" in the list). What it doesn't set still comes from the rules that match. The line names it ("Picked: Nat Geo"), Use the Matching Rules (the arrow after it) goes back, and the pick is kept through a restart and goes with the link to the queue.
- **Sidebar count**: the number of links waiting, beside Pending, leaving out copied links and links from files still being checked.
- **Ways to add links**: an empty Pending lists the same ways as an empty queue, the ones that work on their own first.

## Queue

- **Two at a time**: downloads start in the order they were added, two at once.
- **Download Next**: a waiting download's ⋯ menu moves it to the front, so it starts before the others waiting, even after a restart.
- **Change Folder…**: the ⋯ menu of a download that's waiting, stopped or failed picks another folder for it, and Use the Usual Folder puts it back in the rules' folder (the rule applied to it in Pending, if any). A stopped one asks first, since it then starts over.
- **The whole queue**: on the title's right, Pause All stops every download running and holds every one waiting, Resume All resumes every stopped one, Retry Failed retries every failed one and Clear Finished removes the finished ones. Each does what the row's own button does, and shows only while a download needs it.
- **Posts**: a post's row shows what it holds ("3 images, 1 video"), or how many of its files it takes when some were left out ("3 of 6 files"), instead of a preset, and its progress counts files. On Instagram, X, Pixiv and Tumblr, each file waits a random time first (Settings → Pacing: 3 to 5 seconds on Instagram, 0 to 2 on the others, to start with), so the account isn't blocked.
- **MEGA, MediaFire, Google Drive, Dropbox, OneDrive, pCloud, WeTransfer, the Internet Archive, Yandex Disk, Box, Icedrive, 1fichier, SwissTransfer, Files.fm, upload.ee, TransferNow, Filemail, Workupload and Buzzheavier**: a file host's row shows what it holds instead of a preset. Its progress covers every file together, with the speed limit applied; Stop and Retry continue the file they stopped in.
- **Checks**: when a site Tsundoku downloads from wants to check you're a person (Cloudflare's "Just a moment..."), the download doesn't fail: it waits, its row saying so, while the other downloads carry on, and nothing opens until you choose. This works the same on every such site, and for Workupload and Buzzheavier, whose pages always check first. Open Check shows the site's page in a small Tsundoku window, where you do whatever it asks and click Download. Tsundoku then tries the download itself: if it can, the window stops its own and the row downloads the file with its progress, checked once it arrives where the site gives a checksum; if it can't (the file only comes to the browser that passed the check), the window downloads it and hides, and the row shows its name, size, speed and time left the same way, then moves the file into place under the site's name for it. Only a download from the site itself counts: one from an advert, in a frame or a pop-up, is stopped, and pop-ups to other sites are closed. If nothing happens, the first click went to an advert: click Download again, as the window's title says. The window can't leave the site, never reaches the rest of Tsundoku, and remembers a check you passed, as a browser does; its cookies and sign-ins stay in it. Leave the download for later, or close the window before clicking, and it keeps waiting. Stop or Remove stops the window's download too and leaves nothing behind. In a MediaFire shared folder, the files that don't need the check download first, and the window shows each remaining file's page in turn. Pasting a MediaFire download link copied from your browser for one of those files gets it past the check too.
- **What the check window can't do**: it can't know a file's name or size before you click Download ("Size unknown" until then), takes one file per click, can't list a folder whose page is behind a check (you get the one file you download), and doesn't wait out a site's timer or solve its captcha for you: those are yours to do in the window. Links from a site Tsundoku doesn't support aren't offered the window.
- **One download of a paced site at a time**: while an Instagram, X, Pixiv or Tumblr download runs, the site's next one waits, since two at once would read twice as fast. Settings → Pacing can let a site have up to five at once, each pausing between its files on its own. Downloads from other sites go ahead meanwhile.
- **When a site asks to slow down**: a site that answers that it's getting too many requests (Instagram, most often) doesn't fail the download. It goes back to waiting with what it got, the site's other downloads wait with it, and downloads from other sites go ahead. Instagram's "rate-limit reached or login required", which may mean either, counts as a slow-down while a browser is signed in to Instagram, and as a missing sign-in otherwise. The row says so, such as "Instagram asked to slow down. Continuing at 2:32 PM.", with the time left under it, then it starts by itself. The wait is 5 minutes, then 10, 20, 40 and at most an hour while the site keeps asking; anything from the site that works brings it back to 5. Pause All stops a waiting download like any other, and Resume All or Retry Failed puts it back to waiting, still for its site if the site still waits.
- **Room on the drive**: a download that won't fit on its drive waits instead of starting, its row saying how much the drive has free and how much it needs ("D: has 3.1 GB free, and this needs 14.0 GB."), while the downloads after it that fit go ahead. It starts by itself once there's room: the drive is looked at again every 30 seconds, whenever a download ends or is removed, and on Retry or Resume. What the downloads running on that drive still need counts, and a small margin. Shared files' sizes are exact; a video's is the estimate for the formats its preset picks, read with its link since Tsundoku started. A post of images, or a video whose site gives no sizes, starts as before.
- **Hourly limit**: with Settings → Pacing → Hourly Limit set, an Instagram download waits once the past hour holds that many Instagram files, until enough of them are an hour old, and says so on its row. A post with more files than the limit goes once the past hour holds none.
- **Tries again by itself**: a download whose connection drops goes back to waiting with what it got and is tried again after 30 seconds, 2 minutes and 8 minutes, and only fails if all three drop too. When MEGA's, Google Drive's or Dropbox's download limit is used up, it waits 30 minutes, then an hour, two and four, and never fails for it. The row says why and when it continues, with the time left. Try Now starts it at once (for a site that asked to slow down, the site's other downloads and links go on too); Stop and Cancel work as for any waiting download. Retry, Resume and Resume All start a download's retries over, and Pause All stops a waiting one like any other.
- **Each row**: thumbnail, title, preset, what it's doing (Downloading Video, Downloading Audio, Merging, Converting, Embedding…), size, speed and time left, with a progress bar.
- **Group and sort**: as in Pending, the toolbar groups the downloads by where they stand (downloading, waiting, stopped, failed, done) and by their site, their folder or the rule that picks it, in folding groups, and sorts them by date added, title, uploader or site, either way. Downloads still start in the order they were added, or that Download Next gave them. The choice is kept through a restart.
- **Downloads from one channel, playlist or account together**: the items picked from one source (Download Selected in its picker, from Pending's Pick What to Download too, or a watched source's new items) sit together under the source's own heading, wherever the first of them falls in the sort and in each group they're in: its picture, name, kind and site, where they stand ("3 of 12 done · 2 downloading · 7 waiting", or "12 done" once they all are) and their progress together while any downloads or waits. Its rows hang under it on a line. The chevron, or a click on the picture or name, folds them away; each group remembers it while the app runs. The heading has the rows' actions for all of them at once: Pause All, Resume All and Retry Failed, then Cancel All (×), which asks first and leaves the finished ones, or Clear Finished (×, with Undo) once they're all done. Items picked again later from the same source join the same heading, and so do a watched source's with the picker's. A source with only one download in the queue shows it as any other row. The source is kept with each download, through a restart and Clear Finished's Undo.
- **List, Masonry or Gallery under a source's heading**: the heading has the picker's view toggle and − / + size buttons, remembered for every heading (Gallery to start). In Masonry and Gallery each download is its picture, with where it stands in its corner (its percentage while it downloads), a bar along its bottom, and its title and progress under it; a failed one has a red ring. A right-click on a picture opens its actions (what its row's buttons and More Actions offer: Stop, Resume, Retry, Open File, Show in Folder, Show Log, Copy Details, Download Next, Change Folder…, Cancel or Remove from Queue), and a click shows its full row right under its line of pictures, for its error, its log or its password, without the list jumping. A double-click on a finished download, in List, Masonry or Gallery, opens its file.
- **Stop and Resume**: Stop ends the download and keeps what it got; Resume continues from there. Stopping one that's waiting holds it.
- **Cancel**: removes the download and its partial files.
- **Passwords**: a download whose link needs a password it doesn't have, or whose password no longer opens it, waits instead of failing, its row saying so, with Enter Password: the right one starts it, a wrong one has it ask again. It never tries again by itself. Its password is kept with it through a restart.
- **Failed downloads**: the reason, in plain words with yt-dlp's error under it, and Retry, which continues where it failed. A dropped connection or a used-up download limit is tried again by itself first (see above).
- **Archives unpacked**: a zip, 7z or rar archive a download brings is unpacked beside it once downloaded (Unpacking, with its progress), in one file or split into parts: `.part1.rar`, `.rar` with `.r00`, `.7z.001` or `.zip.001`. Where what it holds goes is Settings → Archives' Where to Unpack, or a rule's: Smart (the default) puts one file or folder as it is and several in a folder named after the archive, In a Folder Named After the Archive always makes that folder, and In Place puts everything beside the archive as it is. A name already taken gets "(2)", so nothing is replaced. A part that another link brings waits for it: the download that brings the last part unpacks the archive. Names that would leave its folder and links inside are left out, and names Windows refuses are made safe. A zip spanned over `.z01` files is left as it is. Then the archive's parts go to the Recycle Bin, or are deleted or kept (Settings → Archives); the History lists what it held.
- **An archive that wasn't unpacked**: the download fails saying why (it has a password, none of the passwords opens it, a part is missing, it's damaged, its drive hasn't the room), keeping every file it downloaded. Retry and Resume only unpack it, without downloading again. Stop while unpacking stops it the same way.
- **Finished downloads**: Open File, Show in Folder and Show Log, until Clear Finished or the row's own Remove from Queue (×), which offers Undo too. They stay in the history. Clear Finished shows "Cleared 3 finished downloads" with Undo for 8 seconds, as Pending's Remove does, which puts them back in their places, unless the same video is in the queue again by then.
- **Show Log**: every download that has started has Show Log, which opens its log under the row, in the app: the log's end (its last 256 KB), following along every second while it downloads unless you scroll up, with Copy Log and Open in Editor beside it.
- **Logs**: each download keeps yt-dlp's full output, kept for 30 days.
- **Copy Details**: a failed download's Copy Details puts what a bug report needs on the clipboard as plain text: Tsundoku's version, each tool's version as Settings → Tools reads it, Windows' version and build, the link, the error as the row shows it and the last 50 lines of its log. A download's password never appears in it, as in its log. The user's name is blanked out everywhere, in paths (C:\Users\<user>, however the slashes are written) and as a word of its own; a name shorter than three letters only in paths, so ordinary words stay. The button says Copied for two seconds.
- **After a restart**: the queue comes back; downloads that were running come back stopped, and waiting ones start.
- **Closing while downloading**: asks first. Downloads continue where they stopped next time.
- **Sidebar count**: the number of downloads not done yet, beside Queue.
- **Ways to add links**: an empty queue says it takes videos, posts of images and shared files, and lists every way to add links, each with where it stands and one button: Paste (what you copied, as Ctrl+V does), Choose File… (files of links, as dropping them does), Watch Clipboard with Turn On or a check once it's on, the Clipboard Shortcut with its keys and Change (or Set Up), and Send from Your Browser and the send buttons with Set Up, which opens Settings → Adding Links at that spot.

## Presets

- **Four to start with**: Best Video (best quality, in MKV, the default), 1080p MP4 (up to 1080p, H.264 and AAC for older devices), Best Audio (the audio as it is) and Audio MP3.
- **Editor**: name; video or audio; for video, the quality limit and the container (MKV, MP4 or as merged); for audio, the format (as it is, MP3, M4A, Opus or FLAC); the file name; the folder (the download folder by default); what to embed (metadata, thumbnail, chapters, subtitles with their languages); SponsorBlock (off, mark as chapters, remove sponsors); and extra yt-dlp arguments. Changes save on their own a moment after the last one, with "Saving…" then "Saved." under the fields; opening another preset or leaving the view saves first, and edits that can't be saved (an empty name, a refused argument) say why and are only dropped after asking.
- **Arguments shown**: the editor shows the yt-dlp arguments the preset gives, as they change. Extra arguments that would break downloads (such as `--yes-playlist` or `-o`) are refused, with the reason.
- **Add Preset** under the list adds one set up as Best Video ships, at the end, and opens it.
- **Set as Default, Move Up, Move Down, Duplicate, Delete**, and **Reset** for the four built-ins. The default is always first in the list: setting another as the default moves it there, and nothing moves above it. Any preset can be deleted except the default, the built-ins included; a deleted built-in comes back as it ships with the ↺ menu beside Add Preset.
- **Kept per download**: a download keeps the preset as it was when it was added, so editing a preset doesn't change downloads already in the queue.

## Rules

- **How Rules Work**: the (?) beside Add Rule explains what each of the editor's fields does (Name, When, Save In, File Name, Start As, Download Right Away and Unpack Archives, with what each of its choices does), so the editor shows the fields alone. Escape or a click elsewhere closes it.
- **Test a Link**: a field at the top of Rules reads a link, without downloading anything, and shows where its download would go, the preset it would start as, whether copied or sent links of it download right away and how its archives would be unpacked, each with the rule that decides it (clicking the rule scrolls to it), or the default preset and Settings when no rule does. A channel or playlist says to test one of its links instead. The answers follow the rules as they're edited.
- **Rules**: "when all of these match, save in this folder, start as this preset, download right away or not, and unpack archives this way". A rule does any of these, at least one. A condition checks the site (by any of its names, such as X, twitter or x.com, with every supported site suggested), the uploader or account (by its name or its handle, so "natgeo" and "National Geographic" both match National Geographic's posts), the title, the link, the kind (video, audio, post of images or shared file) or the preset, with Is, Is Not, Contains, Doesn't Contain, Matches or Doesn't Match, ignoring case unless the condition's Match Case button (Aa) is on, which the rule's sentence then says ("(matching case)"). The kind and the preset have no case to match. A rule without conditions matches every download. Each condition after the first starts with an AND button, on its row, which switches to OR and back, so one rule can mix them: conditions joined by OR are alternatives, and AND joins those, so "site is X OR site is Bluesky AND title contains cat" takes a cat from either site. AND is the default, and the rule's sentence shows each one in capitals.
- **Patterns**: Matches and Doesn't Match take a regular expression (the site, uploader, title or link), found anywhere in the text, ignoring case, shown in monospace. A pattern that isn't valid is caught on Save, with what's wrong with it ("unclosed group"). Text a pattern captures in parentheses can go in the folder as `{1}` to `{9}`, such as title matches `^\[(.+?)\]` → `D:\Series\{1}`; their buttons show under the folder field while the rule has such a pattern.
- **In order**: for the folder, the preset, Download Right Away and unpacking each, the last rule that's on, matches and picks it decides, so a rule overrides the ones above it, and one rule can pick a SoundCloud track's preset and an earlier one its folder. Without a rule picking the folder, a preset's own folder is used, then the first rule's folder, then (with the first rule off) the download folder. Until 0.1.86 the first matching rule decided: rules saved before are turned upside down once, so each still decides what it did.
- **File names**: a rule can name the files of the posts it matches, and a matching shared file (MEGA, MediaFire, Google Drive, Dropbox, OneDrive, pCloud, WeTransfer, the Internet Archive, Yandex Disk, Box, Icedrive, 1fichier, SwissTransfer, Files.fm, upload.ee, TransferNow, Filemail, Workupload, Buzzheavier) when it's a single file, written as Settings → Posts of Images writes it (the editor's File Name, with the same placeholder buttons and an example of the name; "Using Default" while it's empty). {1}, {2}… are what the rule's Matches pattern captured in parentheses: with title matches `(RJ\d+)` and the name `{1}`, "SomefileRJ123456.rar" is saved as "RJ123456.rar". A post's name gets {post} and {number} when it lacks them, so no two files share a name; a shared file keeps its extension. An unknown date, or a {1} the pattern didn't capture, is left out with the separator before it; {account} on a download without one becomes the site, or is left out the same way when the rule's When a Placeholder Has No Value is Leave Out. The last matching rule with a file name decides; left empty, Settings' name or the file's own is used. Videos and audio keep their preset's name, and a shared folder's files their own. A download keeps the name it got when it was added. The row says "Names files “…”".
- **Start As**: a rule's preset is the one matching videos start with, on the preview card, in Pending and for links that download right away; picking another one on the card or the row still wins. Posts and shared files have no preset. A rule that checks the kind or the preset can't pick the preset, since both depend on it. If the preset a rule picks is deleted, the rule says so and the default one is used.
- **Download Right Away**: On or Off for the links it matches, whatever Settings → Adding Links says; Leave as Is follows Settings. It covers what Download Right Away covers: copied links, the clipboard shortcut's and pages sent from the browser.
- **Unpack Archives**: for the downloads it matches, a row of buttons: Skip (left as downloaded), Smart, In Place or Folder (named after the archive), whatever Settings → Archives says (a rule can unpack while Settings doesn't); Default follows Settings. The passwords and what becomes of the archive stay Settings'. It's read when the download runs, so a rule changed while a download waits applies to it. The rule's line says "Unpacks archives: In Place" or "Leaves archives packed".
- **Folders that follow the download**: placeholders in a folder become the download's own, made safe as folder names and cut to 80 characters: `{site}`, `{uploader}` (the name the site shows, such as National Geographic), `{account}` (the handle, such as natgeo, or the name on a site without handles), `{playlist}` (the playlist, channel or account it was picked from in a list, or No Playlist), `{title}`, `{id}`, `{kind}` (Videos, Audio, Posts or Files), `{preset}` (Posts or Files for those, which have none), the upload date's `{year}`, `{month}` and `{date}` (2026-11-06), and `{added}`, the day it was added. A value the download doesn't have becomes Unknown (Untitled for a title), unless the rule's When a Placeholder Has No Value is Leave Out: it's then left out with the separator before it, and a folder whose placeholders all have none goes, so `{site}\{account}` saves a MediaFire file in MediaFire rather than MediaFire\Unknown. The row says "Leaves out placeholders without a value". Clicking a placeholder's button under the folder field puts it where the cursor is, and hovering over it says what it becomes. A folder that isn't a full path goes inside the download folder.
- **Names**: a rule can have a name (the editor's Name field), shown above its sentence and wherever the rule is named instead of "Rule 3": beside a download's folder on the preview card and in Pending, beside a preset a rule picked, in Test a Link, and in the Queue's and Pending's groups by rule. Without one, it's called by its number.
- **Each as a sentence**: "When the site is Instagram and the uploader is “natgeo”", with its number, its folder as it will be used, and what else it does ("Starts as Audio MP3 · Downloads right away"). Drag it by its grip to move it, or Move Up, Move Down, Edit, Duplicate, Turn Off or On, and Delete (after asking). An edit is a draft until Save. Duplicate opens a copy of the rule just below it, as a new rule to change and save; Discard drops it.
- **Everything else**: every install starts with "Everything else → {site}", so each site's downloads get a folder of their own. It's always the first rule ("Always First"), so every other rule overrides it and new rules go at the bottom, and a preset's own folder comes before it too. It has no conditions and only picks a folder: its folder can be changed and it can be turned off, which sends what it took to the download folder, but it can't be moved or deleted. Until 0.1.30 it took only posts of images.
- **Kept per download**: a download keeps the folder and preset it got when it was added, so changing the rules doesn't change downloads already in the queue.

## History

- **History view**: everything downloaded, newest first: thumbnail, title, uploader, site, length, and its latest download's preset, date and size.
- **Search, filters, sorting**: search titles and uploaders word by word, as soon as typing pauses; filter by site, preset, kind (videos, audio, posts or shared files) and when it was last downloaded (today, the past 7 or 30 days, the past year, or between two dates), or show only the downloads whose file is still there, or only those whose file is missing (the Files list: All Files, Only Existing Files, Only Missing Files); sort by date downloaded, title, uploader, site, length, size or preset, either way.
- **Act on several**: tick rows, or all of them with the box above the list (every download the search and filters show, not only those on screen), then Forget Selected, which asks once, or Show Selected in Folder, which opens each folder once with its ticked files selected (only the first when it has to fall back to File Explorer) and asks first when that's more than 5 folders. Changing the search or a filter unticks them.
- **Move Files…**: a row's ⋯ menu, or Move Selected… for the ticked rows, moves every file their downloads made that's still there into a folder you pick, and the history follows them, so Open File, Show in Folder and the duplicate check keep working. A post's or a shared folder's files keep their subfolders, a name already taken gets " (2)", and a move to another drive copies, then deletes the original. It then says how many moved, how many were missing already and why any couldn't be moved.
- **Space on disk**: the line over the list says how much what it lists takes on disk ("5000 items · 412.3 GB on disk"), following the search and filters: every file of every download of those items that's still where it was saved, each counted once. Hovering says how many files that is, and how many more aren't there anymore. It's counted again when a download finishes, after Forget or Move Files…, and when you open the History again, so files deleted meanwhile drop out.
- **Tsundoku's own data**: the same line's right end says how much Tsundoku keeps for the whole history in its data folder ("Tsundoku's own data: 42.1 MB"): its database, the thumbnails it keeps, the downloads' logs (kept 30 days) and yt-dlp's archive. Hovering gives each part's size; the tools and settings aren't counted.
- **Quick at any size**: the history reads more as you scroll and draws only what's on screen, so opening it, searching and scrolling stay instant with thousands of downloads. A row you expanded is still expanded when you scroll back to it.
- **Several downloads**: a video downloaded more than once (as video, then as audio) expands to list each download, with its format, path, Open File and Show in Folder.
- **Posts**: a downloaded post shows what it held ("2 images, 1 video") and expands to list every file it saved, each with its size, Open File and Show in Folder, or File Missing.
- **Actions**: Open File, Show in Folder and Open Source Page, and in its menu Download Again (the link goes in the add bar and its preview opens) and Forget.
- **Forget**: after asking, removes it from the history and from `archive.txt`, so Tsundoku no longer warns before it's downloaded again. Its files stay where they are.
- **File Missing**: a download whose file was moved or deleted says so, and its Open File is off.
- **Thumbnails that don't go blank**: Tsundoku keeps a small copy of each download's picture in its data folder (a post's own first image, a video's picture on the site, or a frame of the video itself), so a row keeps its picture after the site's link stops working, as Instagram's do, or the post is deleted. Downloads from before get theirs in the background, as far as their files or the sites' pictures still allow. Forget deletes it with the rest.
- **Kept for good**: every finished download is recorded, with the video's details, the preset, the file's path, size and format ("1080p · avc1 + mp4a", or "mp3"), and the date. A file yt-dlp found already there is recorded too.
- **yt-dlp's archive**: `archive.txt` lists every video in yt-dlp's own format (`youtube jNQXAC9IVRw`), kept up to date, so yt-dlp on the command line skips them too with `--download-archive`.

## Settings

- **Jump to a section**: while Settings is open, the sidebar lists its sections under it (Downloads, Adding Links… About); clicking one scrolls straight to it, and the one at the top is marked as you scroll.
- **Download Folder**: the folder downloads go in, each site's in a folder of its own by the first rule, unless another rule or the preset picks another folder: picked at the first-run setup, a Tsundoku folder in Downloads by default, with Choose Folder…, Open Folder (which opens it, making it first if nothing was downloaded yet) and Use Default. Rules' folders that aren't full paths go inside it. A portable copy's Downloads folder beside it is saved without the copy's own folder, so it follows the copy to another drive.
- **Archives**: Unpack Archives After Downloading, on to start with; Where to Unpack, Smart (the default), In Place or Folder (named after the archive); After Unpacking, Recycle Bin (the default), Delete or Keep; both as rows of buttons, with what each choice does in the (?) beside Archives, How Unpacking Works. Passwords are tags, tried in order on an archive that has a password until one opens it: type one and press Enter to add it (pasting several lines adds one each), × removes one, and each change is saved at once (blank ones and repeats left out). The passwords are kept in Tsundoku's settings as they are.
- **Downloads at Once**: one to five, two by default. Raising it starts waiting downloads right away.
- **Speed Limit**: for each download, such as 500K or 2M, or none. A value yt-dlp wouldn't understand is refused with an explanation.
- **Default Preset**: the one the preview card picks, also settable in the presets view.
- **Adding Links**: Watch Clipboard, the Clipboard Shortcut, Send from Your Browser, the send buttons' userscript, Take Links from Click'n'Load Buttons, Download Right Away for the links they add (see Pending), Show Notifications, Notify When a Download Fails and Notify When Downloads Finish (see Window).
- **Running in the Background**: Keep Running in the Tray and Start with Windows (see Window).
- **Appearance**: Theme, Auto (the default, following Windows' light or dark mode), Light or Dark, taken at once and from the first frame at the next start. Both themes lay white or lighter cards on a sunk content area.
- **Keyboard Shortcuts**: the window's shortcuts (see Navigation), and the Clipboard Shortcut once one is picked.
- **Posts of Images**: the File Name every file of a post gets, before its extension, made of text and placeholders: {account}, {date}, {post}, {number} and {site}, put at the cursor by the Insert buttons under the field, with an example of the result under them. "{account} {date} {post} {number}" to start with, and Use Default puts it back. A name without {post} and {number}, which could give two files the same name, with an unknown {placeholder}, or with a character Windows refuses in file names (\ / : * ? " < > |) isn't saved, and says why. Each site's own fields fill the placeholders, so a name never says "None": the handle on Instagram and X, and the uploader on a site that gives none. Files downloaded before keep their names; downloading a post again saves it under the new one.
- **Pacing**: a line for each site that blocks accounts reading too fast, "Instagram from [3] to [5] seconds, [1] at once": the pause before each file of its posts, and between its links in Pending, a random time in the range (up to 600 seconds, 0 to 0 for none; 3 to 5 on Instagram and 0 to 2 on X, Pixiv and Tumblr to start with), and how many of its downloads run at once (1 to 5, one to start with), each pausing on its own. Then the Hourly Limit on Instagram's files, "At most [ ] Instagram files an hour", none to start with (see Queue). How Pacing Works (?) explains each. Pauses set before 0.1.147 are kept, apart from Instagram's 5 to 10 seconds and no pause, which take the new start.
- **Cookies**: where to read cookies from, for links that need a signed-in account or an age check. It applies to previews and downloads. Automatic (the default) finds every browser profile on the PC and picks, for each link, the one signed in to its site (by which cookies exist, never their values), or for an unknown site the one that visited it last. A single browser (Firefox, Zen, LibreWolf, Floorp, Waterfox, Chrome, Edge, Brave, Opera, Vivaldi or Chromium) uses its profile signed in to the site, else its default one. Choosing a Chromium browser warns that they lock and encrypt their cookies on Windows; Firefox and its forks work.
- **Supported Sites**: every site yt-dlp and gallery-dl can read, merged into one searchable list without saying which tool reads which, each site once (its playlists, channels and other parts that the tools list on their own are left out). Sites that need an account (Instagram, X, YouTube, TikTok, Reddit, Facebook, Twitch, Niconico, Bilibili) come first, under Signed In with the browser profiles signed in to them, most recent first, or under Not Signed In. The list is read again when Settings opens after a minute, since sign-ins change in the browser.

## Fixes Offered on Failures

- **A site's page couldn't be read**: Update yt-dlp, and Try Nightly when Tsundoku's copy is on Stable, right under the error, on the preview card or the queue row.
- **The video needs a signed-in account**: with cookies off, Set Up Cookies opens Settings. With cookies on, the preview names the site and says whether a browser is signed in to it: "Instagram needs you signed in. Sign in to Instagram in your browser, then try again." or that the site refused the browser's sign-in, with Try Again and Cookie Settings.
- **A post of images while gallery-dl isn't set up**: Set Up Image Downloads sets it up and fetches the post again. A site gallery-dl couldn't read offers Update gallery-dl, which updates Tsundoku's copy (or sets it up in place of yours).
- **An archive with a password**: when it has one and no password on the list opens it, the row has a Password field with Add and Retry, which adds it to Settings → Archives' list and unpacks the archive again, and Archive Settings, which opens that section.

## Tools

Tsundoku downloads with four free tools: yt-dlp, ffmpeg (with ffprobe), Deno, which yt-dlp needs for some YouTube formats, and gallery-dl, for image posts.

### First-Run Setup

- **Where things go, asked first**: before the tools, a first screen asks where the tools go (Tsundoku's data folder, already picked, or a folder you choose; a portable copy also offers In AppData, an installed Tsundoku's tools folder, picked when its tools are already there so they're used instead of downloaded again), where they keep their caches (Tsundoku's data folder or the tools' usual folders in your user folder) and where downloads go (a portable copy's folder beside it, a Tsundoku folder in Downloads, or a folder you choose). The last two start unpicked, and Continue waits for them, so nothing lands anywhere unasked. Back on the tools screen returns to it until a tool is set up. An install set up before 0.1.20 isn't asked: it keeps the data folder's tools, the tools' usual cache folders and its download folder.
- **Found copies**: the first start looks for each tool on this PC (on PATH, such as winget's or scoop's, or Tsundoku's own from an earlier setup) and shows its version.
- **Use This Copy or Download Fresh**: for each tool found, use that copy or download Tsundoku's own; tools not found are downloaded. Each download shows its size and its progress.
- **Official builds, checked**: downloads come from each tool's official releases, on GitHub (yt-dlp's own FFmpeg builds for ffmpeg) or Codeberg for gallery-dl, and are checked against the release's published SHA-256 before they're installed.
- **Antivirus check**: after installing, Tsundoku runs the tool to make sure it's there and works, and says so clearly when Windows Security or an antivirus took it.
- **gallery-dl too**: image posts are as much what Tsundoku is for as videos, so the setup sets up gallery-dl with the others (a copy found, such as an installed Tsundoku's in AppData, is used as it is).
- **Deno and gallery-dl are optional**: the app opens once yt-dlp and ffmpeg are ready. If only Deno's or gallery-dl's download fails, Continue Without Deno (or gallery-dl, or Them) leaves them for Settings → Tools. An install set up before 0.1.25 isn't asked again; Settings → Tools sets gallery-dl up.

### Settings → Tools

- **Update All**: brings every tool that's Tsundoku's own copy up to its latest version in one go, one after the other, then says which it updated and why any couldn't be. Copies you chose yourself are left alone.
- **Each tool's copy**: its version and path, and whether it's Tsundoku's copy or yours.
- **Choose File…**: point a tool at any copy on this PC. Tsundoku checks it's the right program (and that ffprobe is beside ffmpeg).
- **Use Tsundoku's Copy / Download**: switch from your copy to Tsundoku's own, or set up a tool that isn't.
- **Cancel**: stops a download or update in progress, leaving the copy already installed as it was.
- **Caches**: Data Folder keeps yt-dlp's, gallery-dl's and Deno's caches (sign-ins, sites' player code, downloaded scripts) in the data folder's `cache`; Usual Folders leaves them where each tool keeps them in your user folder. It applies from the tools' next run.

### Updates

- **yt-dlp and gallery-dl**: Tsundoku's copies update themselves in the background once a day, at startup and while Tsundoku keeps running (in the tray for days, say), and on demand with Update Now. Settings → Tools says so under each. An update waits until no preview, read or download is using the tool, so nothing running is cut off, and one that fails leaves the copy as it was. gallery-dl is only downloaded again when a newer build is out.
- **Update channel**: Stable or Nightly, which gets site fixes sooner. Switching updates Tsundoku's copy right away, including back from a nightly build to the latest stable one.
- **ffmpeg and Deno**: Check for Updates asks for a newer build, and Update installs it. They're never updated without asking, since they rarely break downloads.
- **Your own copies are never updated** by Tsundoku.
